# v2.0 — macOS対応とARM64バイナリ導入

2026-11-01

Apple Silicon Mac向けのセットアップ・バックエンド認証・Crew起動停止を追加しました。ARM64のParaViewもOSMesaバイナリから導入し、ソースビルドを不要にしました。Windows版の機能は継続して提供します。

## 主な変更

- macOS 15以降のApple Siliconで、専用Colima profileとネイティブDocker CLI／Compose／Buildxを導入します。Docker Desktopは使用しません。
- Homebrewは既存環境を再利用し、未導入ならコミットURL・SHA256を固定した公式インストーラーを起動します。必要なCommand Line Toolsも公式インストーラー経由で導入し、管理者パスワード等は利用者が入力します。
- Mac上に固定版のKiro CLI・Crew・OpenCode・Codex CLI・専用Node／Codex ACPを配置し、既存のCLIやCrew設定と分離します。KASは使用しません。
- Crewを専用launchd jobで管理し、Terminalを閉じても動作を継続します。ログイン時の自動起動は有効にしません。
- ParaView 5.13.3のARM64導入を、conda-forgeのOSMesa版と推移依存のURL・SHA256ロックに変更しました。Windows ARMのWSL、Ubuntu ARM64、MacのColimaで同じ計算イメージ構成を使用します。amd64は従来の公式OSMesaバイナリを継続します。
- 計算イメージのタグを `of2606-r1` から `of2606-r2` に変更しました。OpenFOAM v2606とParaView 5.13.3の採用版数は維持しています。

## Macでの操作

取得したプロジェクト内で実行します。Homebrewの事前手動導入は不要です。

```bash
bash setup/macos/setup.sh
```

Finderからは `setup/macos` 配下の次のファイルを使用します。

| ファイル | 操作 |
| --- | --- |
| `0_Setup.command` | 事前の環境構築とCFDイメージのローカルビルド・検証 |
| `1_StartBackend.command` | Kiro CLI／Codex／OpenCodeの選択・認証 |
| `2_StartCrew.command` | Crew起動と既定ブラウザーでの表示 |
| `3_StopCrew.command` | Crew停止（Colima・計算コンテナは継続） |

通常利用にSSHログインは不要です。hello-world・Nginxの専用検証に代えて、実際のOpenFOAMケースをセットアップで自動実行します。Composeでのコンテナ実行・削除、直列／MPI計算、CPU描画、動画、共有データの永続化・所有権を確認します。コンテナのHTTPポート公開は今回のCFD構成では使用しません。

詳細は [macOS手順](../macos.md) を参照してください。

## 既存環境への影響

Windowsの構築・認証・起動停止の操作は継続利用できます。Windows側のリポジトリを更新するだけで、既存WSL内のCFD環境が自動更新されるわけではありません。`UpdateLaunchers.ps1` は起動ファイルとCrew補助スクリプトの更新用で、CFDイメージの更新は行いません。

既存のv1.0.0環境を削除・作り直す必要はありません。新しいARM64バイナリ構成をWindowsで新規構築する場合は、別のWSL名・保存先で `Setup.ps1` を実行してください。Ubuntuで取得済みのリポジトリ自体をv2.0へ更新した場合は、`scripts/build-image.sh` と `scripts/smoke-test.sh` でr2を構築・確認できます。

配布するのはスクリプト・Dockerfile・設定・ロック・資料です。ParaViewバイナリやビルド済み計算イメージは公開・配布しません。ARM64の取得先はconda-forgeに限定し、Anaconda Distribution・Miniconda・defaultsチャネルは使用しません。

## 実機での確認事項

Colimaを含むApple Silicon Macでの通し構築、Homebrew／Command Line Toolsの初回実導入、個人認証、Crew経由の会話、Finderからの操作は未確認です。標準macOS CIはColimaのネストした仮想化を実行していません。Homebrewの新規導入分岐はダミーインストーラーで検証し、実際のCLI導入にはランナーの既存Homebrewを使用しています。

これらは [macOS手順の実機受け入れ](../macos.md#ci-と実機受け入れ) に記載して継続管理します。Intel Mac・macOSのProxy自動設定は対象外です。採用版と取得元は [設定](../../setup/config/agents.env)、[第三者ソフトの表示](../../THIRD_PARTY_NOTICES.md)、[検証記録](../validation.md) を参照してください。
